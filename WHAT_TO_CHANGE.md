The objective of this repository is to serve as an example on how to implement a platform ops and an API ops pipeline in a federated setup using the Kong Konnect platform and the tools surrounding that environment, like decK or the Terraform provider that Kong Konnect offers. One of the objectives of this repository is that the engineer that is showcasing the capabilities using it can run the examples in his or her own laptop, which is typically a Mac OS-based laptop. To that end, we use the ACT tool. With that objective in mind, we want to avoid relying on third-party infrastructure to minimize the setup environment. Right now, the project is relying on S3 buckets provided by AWS and is also relying on HashiCorp Vault. That is something that I want to change. I want this to use a Minio S3 compatible setup available locally via docker-compose and substitute HashiCorp Vault with Kong Konnect Vault capabilities. And instead of deploying in cloud providers, Kubernetes clusters, I want this repository to be based on a locally available Kubernetes cluster based on ORV stack or Docker Desktop or similar environments. There are as well some references to Dynatrace and Datadog in the repository that we should remove because an observability setup should be a concern of another repository. This repository has not been updated in a while, so probably we need to update the Terraform provider. The latest release is 3.15, and the source code can be found in this directory: /Users/jordi.fernandez/github/terraform-provider-konnect. Those are the immediate objectives. Once we get this right, then I will think about adding new features and functionality. I am open for you to make suggestions on how to improve the current setup without impacting functionality. Any best practices in terms of DevOps platform ops that you can suggest to simplify and streamline, or to make this repository better aligned with industry best practices, I'm open to evaluating your suggestions.
